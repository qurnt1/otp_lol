# Security model

OTP LOL is a local desktop application. The security boundary is designed around localhost traffic, untrusted external responses, and user-controlled settings.

## Local API

- CORS is limited to the development frontend origins.
- The local API accepts only the `127.0.0.1` and `localhost` hostnames. WebSockets require a present exact app origin; only the explicitly enabled development frontend origins are additionally accepted. Missing and `null` origins are rejected.
- Responses include CSP, `X-Content-Type-Options`, and `Referrer-Policy` headers.
- Request schemas reject unknown fields and validate providers, regions, Riot IDs, hotkeys, spells, and preset conflicts.

## External requests

- `/api/assets` resolves known numeric champion, spell, perk, and skin IDs against validated LCU snapshots first; Data Dragon and CommunityDragon paths are restricted fallbacks.
- Absolute URLs, protocol-relative URLs, query strings, fragments, traversal, and unknown path prefixes are rejected.
- Image downloads have timeouts, size limits, content-type checks, format checks, and decode validation.
- Native external links are restricted to the configured HTTPS provider allowlist.

`LcuClient` reuses the League connection already detected by OTP LOL and issues bounded GETs through that local connection. The frontend has typed account/catalog/diagnostics operations, not a URL-taking LCU proxy. The diagnostics runner selects from a fixed endpoint allowlist and sends no LCU write methods. Request records omit headers and credentials; event payloads are bounded and redact sensitive fields and identifiers. Diagnostic export redacts the Riot ID by default, and inclusion is an explicit user opt-in.

Event payloads are not expanded in the diagnostics log list. The **Voir JSON** drawer is the only UI surface that renders their bounded, redacted JSON; endpoint results stored for the current app session contain normalized status, timing, and summary fields only.

Account-statistics cache files contain only normalized DTO fields and freshness timestamps. Cache filenames are keyed by a SHA-256 identity hash; the offline pointer stores only that hash, not the raw PUUID or Riot ID. No LCU authorization, password, or token is persisted in the account cache.

## Statistics providers and WebView bridge

`/api/links/stats` and `/api/links/live` build URLs from a provider selected for that page, a validated Riot ID, and a valid region. Automatic mode prefers a complete connected League identity and uses the last complete locally saved Riot ID/region/platform tuple only while League is disconnected. A connected but incomplete snapshot is unavailable rather than being combined with older account data. Manual values are used only when manual mode is enabled. The detected Riot ID, region, and platform are stored with local settings, but are excluded from portable settings export/import; PUUIDs and LCU credentials are not stored for this feature. The frontend never accepts an arbitrary profile URL. Provider IDs map to registered HTTPS hosts; providers open in top-level native windows or the explicit system-browser fallback. No provider iframe is used and no response is rewritten to bypass X-Frame-Options or CSP.

Non-embeddable providers open in a second top-level pywebview window. Its URL is generated by Python from a provider ID and account settings, is restricted to the registered HTTPS host, and the window is created with `js_api=None`; no `DesktopBridge` methods are attached. This is a reduced application bridge, not a process sandbox: provider content shares the app process/WebView2 runtime, and pywebview may still expose its own `window.pywebview` bootstrap object. The local API rejects unsafe methods (`POST`, `PUT`, `PATCH`, `DELETE`) unless their `Origin` is the app origin or an explicitly enabled development origin. Trusted-host validation rejects non-loopback hostnames. HTTP reads remain protected by the browser same-origin policy and CORS; WebSocket access separately requires an exact permitted `Origin`. A local process is not isolated by these browser controls. `OPEN_EXTERNAL_LINKS_IN_BROWSER` externalizes `_blank` popups, but the documented high-level pywebview API cannot reliably cancel every top-level redirect to a non-provider host. Provider pages may refuse access, redirect, or change without notice; the system-browser action remains available. Real provider rendering requires a manual check with a valid account and the final app flow.

`tests/test_live_provider_audit.py` is an opt-in read-only probe for a real match. In PowerShell, enable it and run the existing `unittest` module:

```powershell
$env:OTP_LOL_LIVE_PROVIDER_AUDIT = "1"
python -m unittest discover -s tests -p test_live_provider_audit.py -v
Remove-Item Env:OTP_LOL_LIVE_PROVIDER_AUDIT
```

It reads the current LCU phase first and sends no provider request unless that phase is `InProgress`; it does not print or persist the Riot ID. It reports each live URL's status, final host, X-Frame-Options, CSP `frame-ancestors`, and likely Cloudflare challenge. This HTTP probe does not prove normal-browser rendering or the pywebview top-level flow; those still require a manual real-match check.

## Persistence and updates

Settings use schema version 6 and atomic writes. A missing file is created on first launch with editable Garen/Lux/Ashe starter presets and every automation disabled. Older or schema-less files are not migrated; they are replaced by those safe defaults without a `.bak`. Invalid files and files from a newer unsupported schema are backed up before replacement. Imports require the current schema version. Release updates require the exact `OTP-LOL-Setup.exe` asset and the matching `OTP-LOL-Setup.exe.sha256` asset. The website displays the release version, date, and checksum when GitHub metadata is available.

The tagged release workflow signs both the packaged application and installer when the required Authenticode secrets are configured, then verifies both signatures before publication. This code audit did not verify a signed artifact from the current HEAD.

## Account identity diagnostics

`/api/account/identity` returns only the normalized Riot ID, provider region, platform ID, regional routing, source, and connection state. Diagnostics show the same bounded identity metadata. Diagnostic exports keep `account_identity.riot_id` null unless the explicit `include_riot_id=true` opt-in is used; no LCU credentials or authorization data are included.

## Interprétation des injections d’erreur navigateur

Les appels normaux vont au vrai FastAPI. Des scénarios ciblés emploient `page.route` pour forcer des états d’erreur ou de transport dans l’interface: `/api/network/status`, `/api/history`, `/api/champions`, `/api/presets/pick_1`, `/api/assets/skins/86/86013/splash*` et `/api/settings`. Ils vérifient le comportement de récupération du navigateur; ils ne prouvent pas que le vrai serveur FastAPI a produit ces erreurs. Les configurations sous `scripts/e2e/` testent séparément le vrai serveur pour les cas API.

Le fichier de réglages utilise le schéma 6. Les parcours E2E de Settings vérifient le rejet du schéma ancien et les opérations visibles d’export/import/reset. Les assertions détaillées de premier lancement, sauvegarde, `.bak` et écriture atomique précédemment portées par les tests Python ne sont pas toutes couvertes par une suite actuellement verte. L’import exige la version courante.

Les champs `auto_detected_*` sont locaux à l’installation, absents de l’export portable et ignorés à l’import. Les scénarios account E2E couvrent l’affichage, la copie/oubli et les valeurs manuelles. La persistance native complète de ces champs reste à revalider après la suppression des tests Python.

## Identity and maintenance checks

Les specs de compte couvrent les identités LCU/manuelle/sauvegardée et les changements de plateforme simulés. Diagnostics couvre la carte d’identité et l’export redacted. Les mises à jour différées et leurs erreurs sont exercées avec une fixture; le passage réel de six heures n’est pas une assertion automatisée.

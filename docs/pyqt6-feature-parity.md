# PyQt6 feature parity contract

## Purpose and scope

This document is the acceptance contract for replacing the Tkinter/ttkbootstrap desktop presentation and desktop integrations with PyQt6. The LCU, champion-select, Data Dragon, settings, history, URL, and update behavior remains the source of truth and must be preserved unless a separate bug-fix decision changes it with regression coverage.

The audit was performed against the code and tests present on branch `codex/future-version` on 2026-07-31. Source code takes precedence over tests, and tests take precedence over `readme.md` when they disagree.

The following are explicitly outside the parity contract:

- There is no current `src/ui_qt/` implementation despite the architecture tree in `readme.md` mentioning one.
- The previous README claimed per-role preset profiles. The code only detects the assigned role and uses roles to filter/sort the champion picker. `src/services/profile_config.py` resolves one global three-slot profile, and `src/config/settings.py` has no per-role profile schema. Per-role presets are therefore a new feature, not existing behavior to preserve.
- Stale `.pyc` files mentioning overlays, Telegram, or old Qt experiments are not source and do not define product behavior.
- The React/Vite website is not rewritten in PyQt6. Its release/download contract is included because it distributes the desktop application.
- Exact Tk widget geometry and ttkbootstrap styling are not compatibility requirements. Information, actions, enabled/disabled states, persistence, keyboard access, and outcomes are.

## Risk scale

- **Critical**: a regression can execute the wrong LCU action, lose user configuration, corrupt runtime state, or prevent safe startup/shutdown.
- **High**: thread boundaries, operating-system integrations, packaging, or reconnect behavior can fail in normal use.
- **Medium**: an important workflow or external integration becomes unavailable, but core data remains safe.
- **Low**: deterministic presentation or convenience behavior with a contained failure impact.

## Required parity gates

The PyQt6 cutover is not complete until all of these gates pass:

1. Every matrix row has either a passing automated test or a recorded manual result for the exact scenario above.
2. Existing core/config/service tests remain green. Tk-specific tests are replaced by `pytest-qt`/`QTest` equivalents before the Tk implementation is deleted.
3. A fake-LCU full-flow test covers connect, ready check, supported/unsupported queue, pre-pick, ban, fallback pick, spells, runes, skin, post-game, disconnect, and reconnect.
4. A real-client Windows smoke test covers LCU discovery, one full champion select, tray, global hotkeys, audio, DPI, shutdown, and restart with existing TOML settings.
5. The packaged EXE passes the same smoke path on a machine without the source tree or development dependencies.
6. A repository search returns no runtime dependency on `tkinter`, `ttkbootstrap`, `ImageTk`, or the old Tk UI modules.
7. The website build and GitHub Pages smoke test pass with final PyQt6 screenshots and a deterministic release asset.

Suggested verification commands after the rewrite:

```powershell
python -m pytest -q
python -m unittest discover -s tests -q
python -m compileall launcher.py src create_exe.py tests
rg -n "tkinter|ttkbootstrap|ImageTk" launcher.py src tests create_exe.py requirements*.txt
npm --prefix website run build
```

The `rg` command is expected to return no runtime matches after obsolete Tk tests and implementation files are removed.

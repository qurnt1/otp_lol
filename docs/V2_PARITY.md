Ce document suit la parité produit et la preuve disponible dans la migration React/FastAPI/WebView. Les anciennes suites Python et Vitest ont été supprimées du tree local. Les derniers runs locaux donnent navigateur **209/209** (après ajout d’un retry borné sur les erreurs transitoires pendant la découverte du faux LCU), API **48/48**, full-stack **1/1** et website **17/17**. Les scénarios utilisent un LCU synthétique et ne prouvent pas le comportement avec League ou WebView2 réels. Le script `npm run test:e2e:api` exécute en série six suites ciblées: account, assets, diagnostics, LCU automation, cache Data Dragon et contrat API. Elles démarrent FastAPI réel et utilisent un faux LCU/fixtures pour les dépendances externes; le dernier agrégat a passé 48/48.

`presets_enabled` est le master gate des automatisations des presets, sans effacer les préférences Auto-Pick, Auto-Ban, Auto-Summs ou Auto-Skin. Les pages de runes restent configurées par slot, avec `rune_page_id = 0` pour conserver la page active. Auto-Accept et Auto Play Again restent indépendants. Dashboard et Réglages partagent ce réglage; l’équivalence du menu tray attend une validation native. Factory reset rétablit les starter presets modifiables (Garen, Lux, Ashe et ban Teemo) et laisse toutes les automatisations désactivées. « Restaurer les presets d'exemple » remet ces choix et coupe le master en conservant les autres préférences. « Effacer uniquement les presets » vide picks et ban sans changer les réglages généraux ni les automatisations. Ces gestes UI ont des scénarios dans `frontend/e2e/settings.spec.ts` et `frontend/e2e/presets.spec.ts`; la suite navigateur a un échec de lancement du faux LCU relancé isolément avec succès.

## Règle de validation

Toute nouvelle fonctionnalité visible doit avoir une entrée ici, un scénario E2E ciblé et une assertion sur son effet observable; si elle traverse le shell natif, une vérification navigateur seule ne suffit pas. Les tests locaux passent par le vrai FastAPI pour les requêtes ordinaires. Certains tests navigateur injectent volontairement des pannes ou erreurs sur des routes API afin de vérifier les états UI; ces injections ne prouvent pas que FastAPI produit la réponse d’erreur. Les tests API ciblés démarrent séparément le vrai serveur. Aucun de ces scénarios ne prouve la disponibilité réelle du client League ni le comportement d’un WebView2 installé sur chaque machine.

## Identity and reliability additions

Les parcours de compte utilisent le résolveur normalisé et `/api/account/identity`; diagnostics expose le tuple source sans secrets, Live explique quand un profil sauvegardé est affiché alors que League est fermé, et les tests de mise à jour utilisent une fixture contrôlée. Les tons de statut runtime sont visibles dans les parcours Dashboard. Les anciennes références de tests Python/Vitest supprimés ne sont plus des preuves et doivent rester retirées des matrices actives.

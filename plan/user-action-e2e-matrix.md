## Périmètre et modèle de preuve

L’interface React expose les pages `dashboard`, `statistics`, `live`, `history`, `settings` et `diagnostics`. Diagnostics n’est pas dans la navigation latérale permanente, il est accessible depuis Avancé et via `#diagnostics` (`frontend/src/app/AppShell.tsx`, `frontend/src/app/routes.ts`). Paramètres comprend les routes `general`, `automations`, `account`, `links`, `shortcuts`, `appearance` et `advanced`.

Le harness navigateur courant ne se limite pas à des composants montés isolément: `frontend/e2e/helpers.ts` démarre un processus FastAPI distinct, sert le bundle de production, traverse les vrais endpoints et le WebSocket applicatif, et dialogue avec un faux client League TLS/WSS piloté par `scripts/e2e/app_server.py`. Le client League est synthétique; aucun scénario ne valide une installation Riot réelle. Les dossiers utilisateur sont temporaires et les requêtes navigateur hors origine sont bloquées. `scripts/e2e/app.integration.spec.mjs` ajoute un scénario traversant redémarrage, stockage, Data Dragon et LCU. Le site marketing est un autre projet Vite sous `website/`, avec son propre E2E.

Pour chaque scénario produit, la preuve recherchée suit le geste clavier/souris, le feedback visible, la requête FastAPI et la relecture de l’état persisté ou l’effet LCU attendu. La couverture native reste séparée. Les scénarios positifs de succès utilisent FastAPI et ses données réelles dans le profil E2E; le faux LCU contrôle uniquement l’état externe de League. Les tests de panne listés ci-dessous emploient `page.route` pour retarder ou injecter une panne HTTP/transport locale, ils vérifient le comportement React de récupération et ne prouvent pas que le serveur FastAPI lui-même a émis cette panne. `helpers.ts` bloque aussi les origines Internet, ce qui n’est pas une injection de réponse API.

Priorités: **P0** bloque l’usage ou peut appliquer une action LoL indésirable; **P1** est un parcours principal ou une protection de données; **P2** est une transition rare, le confort ou une couverture secondaire. La migration a supprimé les tests Vitest frontend de `src/`; le tree courant utilise Playwright pour ces suites. « Couvert dans le code » ne signifie pas que toute combinaison d’états a été exercée. Le dernier frontend complet passe 138/138; API 35/35 et intégration full-stack 1/1. Sur `205d05d`, un des deux jobs Windows Playwright a passé toutes phases; le doublon a échoué uniquement sur l’ancienne assertion timer, corrigée et poussée dans `cf2f836`. Les deux jobs Windows Playwright de `cf2f836` ont réussi. Le run précédent `89d8ac4` avait échoué uniquement à DIAG-01, corrigé dans `205d05d`. Le runner natif avait échoué avec `PermissionError [WinError 5]` dans pystray/Win32 `GetCursorPos`, avant assertions tray; ce scénario reste à confirmer sur desktop interactif. Le self-test du package Windows est passé en CI, sans valider l’interface EXE interactive.

### Interceptions des scénarios d’échec browser

Les succès de lecture et de mutation utilisent FastAPI réel. Les `page.route` ciblant l’API locale injectent une panne de transport/réponse pour tester le retour UI: `GET /api/champions` (503), `PATCH /api/presets/pick_1` (503), `GET /api/assets/skins/86/86013/splash*` (abort), `DELETE /api/history` (503 retardé), `PATCH /api/settings` (abort/422, et 503 ciblé sur la copie d’identité), `DELETE /api/settings/last-detected-account` (503 ciblé), `POST /api/presets/reset`, `POST /api/presets/clear` et `POST /api/settings/reset` (503 au premier appel), ainsi que `GET /api/network/status` (attente contrôlée puis abort). Les retries réussis des actions Settings passent à FastAPI réel; le test d’effacement History vérifie également son retry. Ces injections testent le retour UI, pas une panne réellement émise par FastAPI. Le contexte bloque les origines Internet, ce qui empêche l’egress mais n’injecte pas de réponse API.

# Full-stack application E2E spike

This harness starts the built React frontend from `frontend/dist` through the real FastAPI app and the production `EmbeddedApiServer`, bound to a random loopback port. It creates a fresh profile under the OS temp directory and sets `APPDATA`, `LOCALAPPDATA`, `TEMP`, and `TMP` before importing application modules.

The LCU fixture binds only to `127.0.0.1` on an ephemeral port and uses an ephemeral self-signed TLS certificate. A temporary copy of the current Python interpreter is launched as `LeagueClientUx.exe` with synthetic client arguments. Before connecting, the scenario runs the unfiltered production scanner and verifies that it finds the synthetic PID. It discards all other yielded processes without using them, then constructs `Connection` for the synthetic process to verify argument parsing without opening a socket. Before the production `Connector.start()`, the harness wraps only `lcu_driver.utils.process_iter` so the unchanged `_return_ux_process()` called by `Connector` can yield only that synthetic PID. In the installed `lcu-driver` version, `connector` has no `process_iter` attribute; `_return_ux_process()` is defined in `utils` and resolves `process_iter` there. A real League client installed or running on the test machine can therefore never be selected by the integrated E2E. The actual `Connector`, `Connection`, HTTPS requests, WSS subscription, and application event handlers stay active.

The harness can answer known Data Dragon, CommunityDragon, and GitHub latest-release URLs with small deterministic fixtures at the external HTTP-client boundary; the FastAPI API and its WebSocket are not replaced. `configureExternalState({ dataDragon: "offline" | "online" })` switches Data Dragon responses, while `configureExternalState({ updates: "offline" | "available" | "none" })` controls the GitHub latest-release response. Update checks default to an offline 503; the smoke also switches to a newer synthetic release and verifies it through the real `/api/updates` endpoint. The current smoke exercises Data Dragon outage/retry and champion catalog responses; it does not currently issue a CommunityDragon request. Unknown external requests receive an explicit offline 503 and are recorded as blocked. A socket guard rejects non-loopback DNS and blocks non-allowlisted `connect`, `connect_ex`, and `sendto` calls. Startup invokes all three guards against a documentation-only public test address without opening a socket and reports the verified operations; only the fake LCU port plus the bound API port are allowlisted for outbound TCP. The browser runner also aborts non-app origins. Therefore a fixture request is a logical request to the production external client, but its response is synthesized locally before a network socket opens.

Run the proof from the frontend directory after building the app:

```powershell
python -m pip install -r ../requirements.txt -r ../scripts/e2e/requirements.txt
npm run build
npx playwright test --config ../scripts/e2e/playwright.config.mjs
```

Run the account, asset, diagnostics, LCU automation, Data Dragon cache, and API contract E2E suites sequentially from `frontend/`:

```powershell
npm run test:e2e:api
```

The script runs `account-api.config.mjs`, `asset-api.config.mjs`, `diagnostics-api.config.mjs`, `lcu-automation-api.config.mjs`, `datadragon-cache-api.config.mjs`, and `api-contract.config.mjs` in order, each with one Playwright worker. These specs use the real FastAPI and the controlled fake LCU, Data Dragon, and cache environment as applicable; the contract scenarios exercise invalid requests, CORS, and the WebSocket Origin check.

The spec verifies process discovery and parsed arguments, temporary resolved storage paths, HTTP/TLS access, and WSS subscription. It uses the real UI with fixture-backed champion search, lane filtering/no-results, skin selection, rune-page selection, and Auto-Accept. Initially the fake LCU returns 503 for its game-data version; the UI therefore exercises Data Dragon outage/retry and positive picker data. Before reconnect, the test enables a valid synthetic game version and all six static-data catalogues. It observes the production `static_data.refresh()` requests, verifies `/api/game-data/status` reports all catalogues from LCU, and captures the real `game_data_updated` event after reconnect. It persists `close_app_on_lol_exit=false`, sends real LCU WebSocket gameflow and ready-check events, and waits for the production client to issue `POST /lol-matchmaking/v1/ready-check/accept` to the fake LCU. It then closes the fake WSS connection and synthetic process, verifies `/api/runtime.connected` becomes false, starts a new synthetic process, waits for a second production WSS subscription, verifies the runtime reconnects, and observes another Auto-Accept mutation.

The Node helper in `appServer.mjs` exports `startOtpApp()`. Its result exposes `baseURL`, `stateDir`, `processDiscovery`, `pathIsolation`, `websocketSubscription(s)`, `syntheticLeaguePid(s)`, `externalFixtureRequests`, `externalRequestsBlocked`, `socketEgressBlocked`, `socketConnections`, `emitLcuEvent(uri, data)`, `configureLcuState(state)`, `configureExternalState(state)`, `configureLcuConnection({ online })`, `waitForWebSocketSubscription(number)`, `waitForExternalFixtureRequest(host, path, status)`, `waitForLcuRequest(method, path)`, and `stop()`. The fake's default identity is EUW; `configureLcuState({ region: "NA", platform: "NA1" })` changes the `GET /riotclient/region-locale` response. The valid LCU static-data catalogues are enabled with `configureLcuState({ static_data_online: true, game_version: "16.1.2" })`. `configureLcuConnection({ online: false })` closes the active fake WSS connection, removes its synthetic PID from the process filter, and terminates that synthetic client. `configureLcuConnection({ online: true })` launches a new synthetic client on the same fixture port; the unchanged production connector discovers only that PID and reconnects. This control models the app-observed LCU transport state, not every League client lifecycle transition. Use `stop()` in a `finally` block. It first requests orderly shutdown; if that stalls, it bounds child close waits. It removes its temporary directory only after the app subprocess has emitted `close` and every synthetic League PID is confirmed gone. A timeout leaves the state directory intact for diagnosis. Startup failures include the recent JSON events, process exit code/signal, and stderr in the thrown error. For a same-profile restart, call `stop({ retainState: true })`, then `startOtpApp({ stateDir: previous.stateDir })`; the helper accepts only a previously retained direct child of the OS temp directory, and the final ordinary `stop()` removes it.

This proves browser → built React → real FastAPI → persistent settings → safe synthetic-process discovery/argument parsing → real LCU driver TLS/WSS/event handling, static-data refresh and event delivery, offline/reconnect state, observed LCU mutations, and deterministic picker catalog paths. The integrated `Connector` scan is deliberately filtered to the synthetic process; the test does not prove that a machine-wide unfiltered scan safely selects the right process when a real League client is running. The discovery proof is performed before the filter without constructing a connection to any other candidate. The harness does not launch pywebview, test tray/global hotkeys/native dialogs, model every champion-select write, or prove League build-specific real-client behavior. The fake process does not read or write a League profile.

The certificate helper uses the test-only dependency declared in `scripts/e2e/requirements.txt`; it does not add a production runtime dependency.
